# ML-исследование: есть ли edge?

Модуль `ml/` — это **исследовательская песочница**, а не готовый ИИ-трейдер.
Его задача — честно ответить на вопрос: «есть ли в данных предсказуемость,
которую можно превратить в прибыль после комиссий?» Чаще всего честный ответ —
«нет или очень слабо», и это нормально (см. дисклеймер внизу).

Модуль **не подключён** к живому боту и ничем не торгует. Он только считает.

## Из чего состоит

| Файл | Что делает |
|------|-----------|
| `ml/fetch_data.py` | качает длинную историю Binance в CSV (ключи не нужны) |
| `ml/features.py`   | 33 признака из OHLCV (без look-ahead) |
| `ml/labels.py`     | разметка методом «тройного барьера» (TP/SL/время по ATR) |
| `ml/train.py`      | LightGBM + walk-forward валидация + честный бэктест с комиссиями |
| `ml/requirements-ml.txt` | доп. зависимости (lightgbm, scikit-learn) |

## Установка доп. зависимостей

```bash
pip install -r ml/requirements-ml.txt
```

## Как запустить

```bash
# 1. Скачать историю (напр. 2 года часовых свечей BTC)
python -m ml.fetch_data --symbol BTCUSDT --interval 1h --days 720

# 2. Обучить и честно проверить
python -m ml.train --csv ml/data/BTCUSDT_1h.csv --horizon 12 --tp 1.5 --sl 1.5
```

Параметры `train.py`:
- `--horizon` — на сколько баров вперёд смотрит разметка;
- `--tp` / `--sl` — тейк/стоп в единицах ATR (волатильности);
- `--folds` — число walk-forward фолдов;
- `--threshold` — порог вероятности для входа в сделку;
- `--fee` — комиссия на сторону (по умолчанию 0.04%).

## Как ЧЕСТНО читать результат

- **AUC** — главная метрика качества прогноза:
  - `~0.50` — модель не отличает хорошие сделки от плохих (**edge нет**);
  - `0.52–0.55` — слабый сигнал, легко съедается комиссиями;
  - `>0.55` устойчиво на разных периодах/символах — **повод копать глубже** (но
    сначала перепроверить на утечки данных!).
- **Суммарный PnL (после комиссий)** — если `<= 0`, стратегия не зарабатывает.
- **winrate** сам по себе ничего не значит без учёта размера TP/SL.

## Что защищает от самообмана (это уже встроено)

1. **Нет look-ahead**: признаки используют только прошлое; метки — будущее,
   но при обучении между train и test делается разрыв (`embargo = horizon`),
   чтобы будущие метки train не пересекались с test.
2. **Walk-forward**: обучаемся на прошлом, тестируем на будущем (не случайный
   train/test split, который на временных рядах врёт).
3. **Комиссии** вычитаются из каждой сделки.
4. **Сравнение с базовой ставкой** (доля лонг-побед) — чтобы понимать, лучше ли
   модель, чем «всегда лонг».

## Куда двигаться, если появился намёк на edge

1. Проверить на **других символах** (ETH, BNB…) и **других годах**.
2. Поднять комиссию/добавить проскальзывание — выживает ли плюс?
3. Добавить признаки (мультитаймфрейм, стакан/оборот, фондинг).
4. Только если edge устойчив — подключить модель как **фильтр** к сигналам
   бота на testnet и гонять **месяцами** перед любыми реальными деньгами.

## ⚠️ Дисклеймер (важно)

- Большинство простых ML-стратегий на крипте **не имеют устойчивого edge** —
  это не баг, а реальность эффективного и конкурентного рынка.
- Красивый бэктест ≠ прибыль в реале (переобучение, нестационарность рынка).
- Этот модуль честно покажет «edge нет», если его нет, и не будет подгонять
  красивые цифры. Отрицательный результат — тоже полезный результат.
- Не рискуй деньгами, которые не готов потерять полностью.
